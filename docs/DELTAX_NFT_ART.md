# DeltaX 独特 NFT 立绘

规则版本为 `deltax-unique-v2`。五款软糯原画保留为基础角色，叠加中国元素头饰、颈饰、配色和纹饰，导出透明 PNG。醒狮帽仅限小猫，直接复用用户选定的红金白毛绒醒狮猫原图 `public/pets/deltax-wardrobe-v2/cat-lion-cap.png`，不再使用旧矢量狮帽；帽子保留原色，颈饰按配色与纹饰组合。原始五款仍用于游客花园，新版首页读取完整立绘预览；新 NFT 通过独立 `DeltaXGlowpet` 合约引用完整立绘。

当前完成的是本地生成、去重、元数据及合约接入。**尚未上传 IPFS、尚未部署或发行。** 默认生成 100 只只是本地版次数量，可以在生成时另行指定，不代表已经铸造或公开发售。

## 组合与唯一性

组合空间为 **(5 × 7 + 1) × 8 × 8 × 8 = 18,432**：七类共用头饰覆盖五种宠物，醒狮帽额外仅供小猫使用。小猫有 4,096 套组合，其余每个物种各 3,584 套。旧 `v1` 预览仅作存档，新规则不重新解释已发行版本。

| 维度 | 选项 |
| --- | --- |
| 物种 | 兔、猫、狐、鼠、羊 |
| 头饰 | 玉簪、梅花、桂花、丝绸蝴蝶结、蝶形夹、云纹梳、莲冠；醒狮帽仅供小猫 |
| 颈饰 | 中国结、丝巾、云肩、香囊、玉坠、青花瓷坠、织锦领、长命锁 |
| 配色 | 朱砂、青瓷、靛蓝、荷花、琥珀、翡翠、紫藤、珍珠 |
| 纹饰 | 祥云、莲花、梅花、竹、波浪、如意、月、锦鲤 |

这些维度都有实际可见的配饰或纹样，不用编号、背景颜色或透明像素差异充当独特外观。导出器同时检查属性组合和最终解码 RGBA 像素的 SHA-256；完全透明像素的 RGB 先归零，再比较像素。发现重复即停止，不发布不完整清单。像素不重复并不替代人工审美检查，预览页用于比较缩略图与配饰遮挡情况。

每张图的属性按实际组合输出，清单统计物种和各配饰的真实出现次数；本版没有人为标注普通、史诗、传说等主观稀有等级，也没有通过加权随机抽取牺牲去重保证。

## 固定分配规则

- 每次部署固定 `editionSize`（1–18,432）与 `artworkSeed`（32 字节十六进制，允许全零）。种子是公开的美术参数，**不是领取凭证或私钥**。
- 合约创建系列时，为该系列的全部 `maxSupply` 永久预留连续索引。每只的索引是 `seriesArtworkOffset + serial - 1`。创建失败不消耗额度；关闭系列也不回收额度。
- 用互质仿射置换映射到有效组合序号：`a = ((uint256(seed) >> 128) % 18432) | 1`，当 `a % 3 == 0` 时令 `a = (a + 2) % 18432`；`b = uint256(seed) % 18432`；`rank = (index * a + b) % 18432`。18,432 只含质因数 2 与 3，所以映射一一对应。
- `slot = rank % 36`：槽位 0–34 对应五物种的七类共用头饰（物种为 `slot % 5`，头饰为 `slot / 5` 向下取整），槽位 35 只对应猫与醒狮帽。颈饰、配色、纹饰从 `rank / 36` 的三个八进位数解码。
- 最终图片编号继续使用 `speciesIndex + 5 * headwear + 40 * floor(rank / 36)`，因此编号空间仍为 0–20,479 的稀疏子集，但有效组合只有 18,432 个。不要把有效数量与最大文件编号混淆，也不承诺任意五个连续分配恰好覆盖五物种。
- 唯一性承诺限于**同一合约版次中的所有系列**。不同部署可使用相同图片或种子，不宣称全世界或跨合约唯一。
- 领取顺序、钱包、刷新、转让和成长都不改变外观；成长只更新 `Stage`。系列创建顺序决定预留区间，发行计划需记录系列和索引范围。

规则实现位于 [`shared/deltax-traits.js`](../shared/deltax-traits.js) 和 [`contracts/DeltaXGlowpet.sol`](../contracts/DeltaXGlowpet.sol)。合约测试核对 JavaScript 与 Solidity 的种子边界、属性解码及分配一致性。

## 生成和核验

```text
node scripts/generate-deltax-edition.mjs
node scripts/generate-deltax-edition.mjs --verify output/deltax-unique-v2/publish/collection.json
```

默认输出 100 张 1254 × 1254 透明 PNG，目录为 `output/deltax-unique-v2`。可以使用 `--out`、`--supply`、`--seed`、`--size` 生成其他版次；已有输出目录会被拒绝覆盖。种子必须是完整的 `0x` 加 64 位十六进制字符，数量不得超过 18,432。冻结版次后，不更换规则、种子、原图或图片内容。

输出结构：

```text
output/deltax-unique-v2/
  index.html                 本地可筛选预览，不上传
  preview.png                本地预览总览，不上传
  publish/                   只上传这个目录的内容
    collection.json          公开版次参数、文件校验和、属性及频次
    portraits/<id>.png       最终完整透明立绘
```

`collection.json` 中每项同时记录连续的 `globalIndex` 和置换后的 `appearanceId`。小于总容量的版次会使用不连续的外观编号，不能把文件名擅自改成 `0..editionSize-1`。清单和图片不包含 NFC/QR 领取密钥、Merkle 凭证、账号或钱包私钥。

核验器重新核对容量、置换参数、渲染器与规则源码校验和、五张批准原图及猫专属醒狮原图、Sharp/libvips 版本、文件尺寸、PNG 文件校验和、解码像素校验和、所有预期属性、组合与像素去重，以及完整频次统计；返回清单 SHA-256 用于部署记录。源码哈希统一换行后计算，核验应在冻结版本及锁定依赖的环境中进行。

完成清单先写为 `collection.pending.json`，全部核验与预览成功后才提交为 `collection.json`。核验器拒绝残留 `INCOMPLETE.txt`、多余发布文件及符号链接目录；失败输出不得发布。上传目录只能包含规定的清单与立绘文件。

## IPFS 与发布

1. 生成完整版次并执行核验，检查预览。保留原始清单和 SHA-256。
2. 将 **`publish/` 的内容作为 IPFS 目录根**上传并持续 pin，保留 `collection.json` 与 `portraits/` 路径。取得实际 CIDv1 dag-pb / SHA-256 目录 CID（59 位小写 base32，以 `bafy` 开头）。脚本不会上传，也不制造占位 CID。
3. 通过至少两个网关下载清单及图片并核对 SHA-256。下载后的目录还应运行本地核验。只有实际上传并持久 pin 后才有可用于发行的 CID；本地文件检查不证明远端存储可用。
4. 编译并部署 `DeltaXGlowpet(directoryCID, editionSize, artworkSeed)`，数量和种子必须与已核验清单一致。构造函数会创建固定参数的 `DeltaXPortraits`，不另行部署旧版 `GlowpetFaceArt` / `GlowpetArt`。`art()` 是实际的新外观合约地址。
5. 按原 v2 协议建立系列，所有系列预留数量之和不得超过版次上限。将新合约地址同步到前端、后端和代付白名单；领取授权必须使用新地址对应的 EIP-712 域。
6. 在目标网络实际领取，验证元数据的 `Species`、`Headwear`、`Neckwear`、`Palette`、`Motif`、`Appearance`、`Artwork`、`Stage` 与图片一致，检查转让和成长后图片不变，以及首页、收藏、详情、花园和挂件预览均能读取。

NFT 的 `image` 直接为 `ipfs://<CID>/portraits/<appearanceId>.png`；像素保存在 IPFS，所有权、版次规则、外观分配和返回的元数据在链上，**不称为全链上图片**。公共网关或 pin 不可用会影响加载。

## 本地部署接线

`scripts/deploy-local.mjs` 仅用于本地演示，会写入本地前后端配置，不能当作线上部署脚本。

- 未设置 `DELTAX_ART_CID`：保留原 SVG 演示流程。
- 设置真实 `DELTAX_ART_CID`：必须有完整已核验版次。`DELTAX_ART_MANIFEST` 默认指向 `output/deltax-unique-v2/publish/collection.json`。
- 在发起部署前，脚本调用 `verifyEdition` 检查全部图片，并拒绝超过版次上限的本地系列。
- 构造参数取自核验结果；部署后再读取合约的版本、数量与种子核对。部署记录保存实际 `art()`、版次参数、清单 SHA-256 及核验图片数量，不会把旧 SVG 绘图合约误记成新外观合约。

本地编译、测试和导出成功不等于已上传、已部署或已发行；仍需完成持久 pin、内容核验、目标网络部署和真实领取验收。
