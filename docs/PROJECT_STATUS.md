## 本轮实际检查

环境：macOS、Node.js **24.19.0**；标准安装分别用 npm **10.2.3** 和 **11.21.1** 复现。Git HTTPS 拉取超时，因此从 GitHub Git Data API 取得指定提交的源码与素材，下载内容按 Git blob SHA-1 核对，在隔离目录运行检查，未覆盖原工作目录及其私密配置。以下结果不是沿用 10/28 旧设备记录。

临时安装参数会跳过 peer 依赖校验，仅用于继续诊断。上述测试通过不代表标准安装已修复，也不代表该安装方式适合发布。失败结果只描述本轮隔离环境，不推断现有公网游客站是否正常。

## 下一步顺序

1. **恢复可复现安装和游客构建**：在隔离分支检查 `@lit/react` 引入的 React 类型 peer 与 Privy/Stripe 依赖闭包，补齐锁定依赖，审查差异，避免升级无关包。不得仅将 `--legacy-peer-deps` 写入项目配置作为修复。
2. 使用普通 `npm ci` 重新验收，再运行测试、立绘核验和 `build:visitor`；完成最新版首页、猫专属醒狮帽、五角色花园与基本养成操作的浏览器检查。
3. 真实账号、云花园、代付和 NFT 发行需要实际服务配置及单独验收；按 [部署说明](ONBOARDING_DEPLOYMENT.md) 和 [立绘规范](DELTAX_NFT_ART.md) 推进，不把 mock 或本地链成功当成上线。
4. 托管、DNS、备案与购买云资源仅在用户恢复对应任务后推进。
